# 保留原模型，完成飞桨人员躺卧告警 Demo

> **已停用，保留为历史方案（2026-10-16）。** 用户已决定采用 YOLO11 Human Fall Detection，`fallen` 单次命中立即报警，取消2秒确认，不再接入或训练飞桨模型。当前方案见 [YOLO11躺卧即时告警-demo实施计划.md](./YOLO11躺卧即时告警-demo实施计划.md)。以下内容不再作为执行指令。

保存日期：2026-10-16。

执行顺序更新：先独立评测已下载的 YOLO11 Human Fall Detection 候选，暂不启动下面的飞桨训练。按用户最新要求，YOLO11 只测试飞桨失败子集（躺卧漏报及普通活动误报），不运行整个数据集；另检查已有两段演示视频。下面保留此前确认的完整飞桨实施方案。

## 目标与边界

- 原 YOLO 权重、旧 demo 和 ROS2 默认配置保持不变；新增独立飞桨检测分支。
- 本轮目标是**识别人员已经躺卧的状态**，主动躺下也报警，不要求先观察到跌倒过程，不区分床和沙发。
- 优先减少漏报；默认确认持续躺卧 **2 秒**后发出声音和画面警报，正常处理情况下首报控制在约 2～3 秒。
- 完成电脑上的视频、摄像头 demo；本轮不部署小车、不控制底盘。已下载的 YOLO 跌倒权重暂不启用到此飞桨方案中；上述独立候选评测不改变这一方案。

## 模型与准确率改进

- 新分支采用 **PP-YOLOE 人员检测 → 跟踪 → HRNet 骨骼 → ST-GCN 躺卧分类**，直接读取完整原始画面，不依赖原 YOLO 先检测到人。
- 将 ST-GCN 微调为“躺卧／其他”两类，加入静止躺卧、视频开始时已躺卧的训练样本；正常走动、坐姿、弯腰、蹲下和跪地保留为负样本。
- 对新增分支的 PP-YOLOE 补充卧姿难例微调，解决躺卧时无人员框的问题；从现有检测生成候选标注，检查并补齐漏框、纠正误框。HRNet 暂时冻结。
- 恢复官方可训练的 ST-GCN 结构，通过参数映射迁移部署权重。先验证恢复前后推理一致、反向传播产生有效梯度，再训练；当前部署模型直接加载后的反传检查没有得到参数梯度。
- 所有新增训练结果保存到独立版本目录，不覆盖官方权重。固定随机种子；训练参数、标注、数据划分和模型指纹随结果保存。
- 使用 **50 样本因果滑动窗口，每 0.2 秒更新判断**，替代非重叠窗口；启动不足长度时重复首个有效骨骼填充，训练和推理保持一致。尾段可推理，但不能虚构后续观察时间。
- ST-GCN 默认使用 AdamW、学习率 `1e-4`、批量 32、最多 50 轮、验证早停 8 轮；检测器采用官方 PP-Human 人员配置，640 输入、AMP、批量 2、最多 20 轮，显存不足降为批量 1。

## Demo 与告警接口

- 新增独立启动入口，支持视频路径、摄像头编号、模型目录、设备、配置、输出目录和无窗口批处理。
- 摄像头仅采集一次；原 YOLO 和飞桨分别在已有独立 Python 环境的工作进程中运行，避免两套 GPU 依赖相互影响。
- 视频评测逐帧处理并使用视频时间；摄像头模式采用有界队列、优先最新画面。结果携带帧编号和采集时间，过期结果不参与新告警。
- 每个人独立维护告警状态：累计有效躺卧观察达到 2 秒触发一次；短暂缺测保留候选但不增加确认时间。明确非躺卧持续 1 秒结束事件；目标丢失记录为“失去观察”，不显示成已恢复正常。
- 界面显示人物框、躺卧分数、确认进度、报警状态和处理帧率；首次报警保存截图，支持保存标注视频。
- 采用非阻塞声音警报，支持静音、重置和退出。声音不可用时明确显示提示，截图和日志继续保存。
- 沿用现有事件记录字段，新增事件类型 `person_lying`，附加模型版本；推理结果明确区分有效判断、无法判断和运行故障。接口可供后续 ROS2 节点复用。

## 数据评测与验收

- 使用现有全部 **69 段数据**，按完整视频分组、按跌倒／主动躺卧／普通活动分层做五折评测；阈值只在各折训练侧的验证集选择，禁止相邻帧跨训练和测试集合。此项属于后续飞桨实施方案，当前 YOLO11 对照测试仅跑上述失败子集。
- 现有“正常”和“倒地”视频留作演示检查，不加入训练。统一计分目标为所有躺卧，同时保留真实跌倒子集结果。
- 对比原方案、官方飞桨默认流程、改进流程和微调模型，分别报告躺卧帧召回、误报片段数、事件报出率、报警延迟，以及检测／骨骼／分类各环节的漏检。
- **现有 30 段跌倒视频只有 3 段的躺卧标注跨度达到 2 秒。** 全部片段仍保留实际报出统计，另外列出观察时长不足的情况；不循环、冻结或延长视频来凑报警。
- 验收目标：躺卧帧召回率达到 90%，普通活动误报片段比例不超过 10%；持续可见且满足观察时长的躺卧片段，目标事件报出率达到 90%。报告必须列出分母和实际结果，未达到目标不能写成已达标。
- 自动测试覆盖：开始时已躺卧、缓慢躺下、正常动作、多人独立计时、短时漏检、重复及过期帧、模型故障、短视频结束、声音不阻塞、截图日志一致，以及原功能回归。
- 交付可运行 demo、新模型与配置、训练及评测命令、完整报告、标注视频和成功／漏报／误报截图。URFD 与官方预训练数据存在重叠，结果标为本地回归与微调评测；小车真实低视角效果留到实机阶段验证。
