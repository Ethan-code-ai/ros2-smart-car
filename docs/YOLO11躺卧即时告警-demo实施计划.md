# YOLO11 躺卧即时告警 Demo：当前实施方案

更新日期：2026-10-16。取代此前飞桨方案及2秒确认要求。

## 已确定的行为

- 保留原通用检测权重 `ros2_ws/src/smart_car_decision/models/yolo11s.pt`，新加独立的 `yolo11-fall.pt`。不修改原模型、旧 demo 或小车 ROS2 默认配置。
- 当前方案不加载飞桨模型，不采用飞桨与 YOLO 的 OR 融合，不启动飞桨训练。历史文件仅作留档。
- 专用权重直接输出 `fallen / sitting / standing`。输入640，置信度0.25，FP32，GPU `cuda:0`，沿用已完成全量测试的设置。
- 当前帧出现任意 `fallen` 且置信度≥0.25，**在该帧立即产生画面和事件告警并请求系统提示音**。没有2秒确认、多帧投票、宽高比或跟踪ID门槛。
- 主动躺下、视频开始时已躺卧同样报警。本模型本身不能可靠区分地面、床或沙发，本轮不增加这类过滤。
- 每帧显示当前告警状态；连续命中时合并为一个场景事件，消失即结束，再命中立即重新开始。合并事件不延迟首次报警；不承诺人员身份跟踪。

## 实现与使用

- 独立入口：`demo/yolo11_fall_demo.py`；公共告警逻辑：`demo/fall_alarm.py`。
- 单次读取摄像头／视频完整原始帧，两套 YOLO 独立推理；先执行跌倒分支并触发告警，再执行原通用分支。原通用模型漏人不会阻止跌倒告警。
- 两模型共用现有 `.venv-demo` GPU 环境，无需安装 Paddle。声音使用 Windows 异步系统提示音，不阻塞读帧；`--mute` 仅关闭声音。
- 输出独立目录，包含环境、逐帧两模型输出、告警开始／结束事件、首次命中截图和可选标注视频。旧结果不覆盖。
- 本轮完成本地视频／摄像头 demo。小车部署仍需单独适配共享图像话题和告警消息，不改变底盘控制。

## 验证与已知效果

- 复用已验证的69段、11756帧预测缓存，按即时告警重新计分，不重新推理或调参。新结果保存至 `demo/results-yolo11-fall-all-immediate/`。
- 即时告警必须逐帧等于当前 `fallen` 信号；短片、首帧躺卧、新目标、重复时间戳均不能增加等待。
- 既有全量结果：真实跌倒28/30，含主动躺卧共40/46；普通活动12/23段出现误报。即时策略继承这些模型误判，不能把取消等待解释为准确率提升。
- 补跑两段本地视频验证新 demo 的双模型加载、CUDA/FP32、首次事件时间、截图和视频可解码性；不将无人工标注视频计入准确率。无界面测试使用静音，现场音量／扬声器另做实际试听。
- 原始评测和飞桨结果留存；需要复现历史时序策略时显式指定 `--confirm-seconds 2`，它不是当前 demo 的参数。
