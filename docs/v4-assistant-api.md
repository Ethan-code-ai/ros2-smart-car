# v4 助手会话和草案

独立主机通过 `ASSISTANT_BASE_URL`、`ASSISTANT_MODEL` 和 `ASSISTANT_API_KEY` 配置 OpenAI-compatible Chat Completions。地址使用 HTTPS，写到 API 前缀，例如以 `/v1` 结尾。也可设置 `ASSISTANT_API_KEY_FILE` 从秘密文件读取密钥。管理员在「系统设置 → 智巡助手」启用连接。服务响应只报告配置是否存在和启用状态。

登录用户通过 `/api/v1/assistant/sessions` 建立或查询自己的会话。向 `/sessions/{id}/messages` 提交 `client_id` 和 `text`。相同请求 ID 与内容重复提交时返回已保存结果。换用内容需生成新的请求 ID。会话历史和草案通过 Bearer 鉴权，权限不能跨会话转让。

模型可读取绑定车端的状态、停车条件、地点和路线，也可以提议最多六步的草案。草案使用业务资源引用，由主机和车端校验地图及配准，保存资源版本、计划摘要和五分钟有效期。模型工具不包含运动接口。

从桌宠浮窗可以对话、查看草案和资源名称，也可以打开会话历史。确认使用 `POST /plans/{id}/confirm`，提交草案的 `version` 和 `digest`。服务器重新校验权限、车辆能力、地图和资源版本。重复确认返回同一执行记录。确认后的队列记录可查询和取消，独立停止也会撤销对应车辆尚未派发的计划。

`GET /events?after=...` 通过 Bearer 鉴权提供事件流，客户端使用事件 ID 恢复。只有会话所属账号能读取对应事件。待确认事件会展开浮窗，处理过的事件按账号去重。

后台执行器逐步派发，并为每一步保存稳定运行 ID。运输到取件点后等待装件，送达后等待交接。搜索发现目标并停稳后等待人工决定是否继续余下计划。人工操作通过 `POST /executions/{id}/actions` 提交动作和当前执行版本。

启动后先对账遗留任务，暂停自动推进。状态不明时只查询已有运行记录，不自动重发。独立停止撤销后续步骤，桌面正常退出也会保存取消请求并尝试取消对应车端任务。离线时保留取消待核实状态。

`GET /reports/{id}` 返回会话内保存的异常报告，`?format=markdown` 下载 Markdown。读取需要报告归属和异常读取权限。事件范围使用上海日期转 UTC 的左闭右开区间，数据库按类别和处理状态计数。模型可以选择已查到的重点事件，报告数字与确认状态来自数据库。当前绑定车辆的上报采样按分钟记录，缺失时段显示覆盖未知。缺少发生时间的事件单独计数。

Windows 桌面在启动窗口的「凭据设置」保存模型地址、模型名称、模型密钥和车端机器凭据。系统凭据按当前 Windows 用户和应用数据目录区分。配置后在 Web 系统设置中启用模型。车端机器凭据须与车端部署时配置的值一致。

模型与车端执行验证使用模拟提供器和模拟车辆，移动能力仍依赖逐项实车验收。


新增受限前进move_relative、管理员单次现场授权和重新核验草案接口见[v4-agent-control.md](v4-agent-control.md)。这些接口调用现有控制服务，不从模型自由文本中执行命令。当前交付按用户要求停止实车及模型验证，不能将此前草案测试视为新动作的完整实车验收。
