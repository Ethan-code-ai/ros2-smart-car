## 3. 保留的产品行为与参数

主动避障继续作为全局共享控制层，首次默认开启，之后保留操作者设置。手动、建图、自动巡航、颜色追踪、人物跟随使用主动绕行；地图导航由 Nav2 规划，共享层只限速或停车，不增加转向。

手动松手、输入超时、目标丢失、红灯、停止和急停均优先于绕行。关闭主动避障只关闭主动绕行，最低防撞、传感器故障停车和急停继续生效。设置仍要求停止模式和新鲜里程计确认静止，控制器确认后才显示生效。重启、重连、解除故障和更新设置均不得自动恢复运动。

| 参数 | 本轮要求 |
| --- | --- |
| 日常绕行速度 | 原模式前进速度的 80%，上限 0.25 m/s；空间或数据不足时进一步限速或停车 |
| 绕行角速度上限 | 0.25 rad/s |
| 主动触发距离 | 默认距车体前缘 0.60 m，可设置 0.40～1.50 m；保留已保存值 |
| 恢复条件 | 至少 0.75 m 或触发距离加 0.15 m，取较大值；持续畅通 0.5 s |
| 车体包络 | 当前默认半径 0.25 m，实测核对，与导航保持一致 |
| 最低防撞余量 | 0.15 m，并考虑速度、数据延迟和制动距离 |
| 数据超时 | 雷达 0.6 s；里程计 0.5 s；TF 无效和里程计跳变停车 |
| 单次绕行限制 | 15 s 或 1.5 m；本轮不擅自放宽，超限停车并解释原因 |

用户已认为 0.08 m/s 的日常绕行上限过低，不要改回该值。首轮现场测试可单独限制低速。不能承诺全程等速；转向、可见范围和制动能力可能要求减速。若 15 s 限制频繁导致正常路径失败，记录各阶段耗时另行给出证据，不通过放宽限制掩盖路径问题。

## 4. 控制算法修复

### 4.1 先建立真实扫描样本

静止采集短时原始 `/scan`、扫描时刻 TF、里程计、驱动参数和控制状态。分别统计有限有效值、`+Inf`、`-Inf`、NaN、零值、超量程值及角度缺失，输出车体坐标下的前后左右覆盖情况。保留原始角度顺序、安装偏移和时间戳，制作可重复回放的脱敏测试样本及 SHA256。

核查雷达反装、驱动角度裁剪和车体遮挡。先确认无回波值的驱动含义；未经确认的无限距离不能当作空地。不要大范围删除近处点，也不要把后半圈批量补成最大距离。若存在自反射，先通过静止标定和实际安装结构确认，再采用范围明确、可测试的处理方式。

### 4.2 分开检查障碍与未知区域

主要修改 `ros2_ws/src/smart_car_decision/smart_car_decision/avoidance.py`，建立可独立测试的几何检查接口，分别返回：碰撞风险、所需区域是否可观测、最近净空、失败位置和稳定的原因码。

已观测到的近障点始终参与检查，包括单点小障碍。未知区域按当前动作是否会接近或扫入该区域处理，不再无条件要求整圈膨胀圆可见。例如，正前方及前进所需的侧向区域已观测并足够宽，后方缺失且车辆不会扫入或接近该盲区时，不能仅因后方缺失阻止直行；后退所需区域未知时仍应停车。

必须检查从当前速度到停车的整段轨迹，包括数据年龄、控制延迟、制动距离、轨迹曲率和车体包络。只检查车头中心射线或一个前方扇区不足以证明可通行。

实现时遵守以下边界：

- 只有车辆实际占据的物理空间可以作为当前车身的几何基准，不能把半径 0.40 m 的整片安全余量或上一次通过的区域直接标为“已知空地”。已有真实回波不能因落在该基准附近被自动忽略。
- 区分当前占据区域、未来新扫过区域和安全余量。若允许某个未知区域保持在后方，需用几何测试证明动作不会接近或扫入它，并说明适用条件；不能声称已验证该盲区内具有 0.15 m 净空。
- 后退、横移、弧线和转动分别依据实际运动检查。实际车体不是理想圆时，转动会扫过角部；不能因中心不动就默认旋转安全。只有包络与扫过区域得到验证才允许该动作。
- 相邻雷达射线间的空间推断须有角分辨率、距离和最小检测障碍尺寸依据；不得用任意插值填平窄障碍或大段盲区。
- 使用扫描时刻 TF，并将观测补偿到当前车体坐标。不要依赖 SLAM 地图作为手动行驶前提，也不能用静态地图填补当前动态障碍观测。

若真实传感器覆盖不足以支持某种转向，安全结果应是限制该方向并说明缺失区域；必要时修复驱动配置或安装覆盖。不能为了通过“必须能绕行”的测试放行未知区域。

### 4.3 统一修复所有调用位置

逐一检查 `step()`、`guard()`、`choose()`、恢复方向阶段中的 `free_disk()` 和 `free_segment()`，避免起步放行后又被其他阶段的整圈检查拦住。优先共用一套几何与可观测性逻辑，避免模式之间规则冲突。

选边不应要求车辆当前就看清被障碍遮住的整条远期绕行路线。采用短距离、可停止的局部轨迹滚动检查：只执行当前已证实安全的前缀，后续随新扫描重新验证；若前缀不足以保证停车则不执行。保留连续两帧选边确认、单次方向锁定、左右同分优先左侧，防止频繁左右切换。单帧近障仍可触发保守停车。

恢复阶段同样检查实际转动和前进区域；恢复原朝向不等于回到原车道。手动释放或跟随目标失效时取消所有路径和恢复动作。保留超时、距离上限和堵塞锁定，重新发起运动才允许重试。

`decision_controller` 继续作为 `/cmd_vel` 的唯一发布者。算法、Web 服务、诊断工具和测试脚本均不得另开底盘速度出口。控制循环超预算、数据过期或异常时应有明确的停车路径，不能继续发布缓存的非零速度。

## 5. 停车原因、状态与界面

现有 `avoidance` 状态增加兼容字段，具体名称可统一调整，但至少表达以下信息：

| 字段建议 | 用途 |
| --- | --- |
| `reason_code` / `reason` | 稳定原因码与中文说明，区分真实近障、所需方向未知、数据超时、配置未确认、超限、操作者停止 |
| `requested_motion` / `applied_motion` | 原运动意图与最终输出，定位“收到请求但被拦截” |
| `coverage` | 与当前动作相关的覆盖状态及缺失方向；避免只给一个整体有效率 |
| `last_stop_event` | 最近一次安全拦截的时间、模式、阶段、原因、净空和数据年龄 |
| `build_id` | 车端代码构建标识，用于与安装包交付记录对应 |

当前状态和最近一次安全拦截分开保存：松手后当前状态可以显示“已停止”，但最近一次拦截原因仍可查询。普通停止事件不应覆盖上一条有用的安全拦截；历史诊断也不得重新触发运动。默认保留本次服务会话的有限记录即可，不引入无界日志或新的数据库。

在状态转换和原因变化时记录日志，连续重复事件节流；建议限制内存历史条数并配置文件轮转。日志应能关联请求、控制器实例、原始意图和最终输出，不输出密码、密钥或每帧整组雷达数据。车端磁盘紧张，不得长期无界录包。

修改范围包含车端状态/API、状态 WebSocket、前端共享运动设置、桌面代理和必要的兼容测试。运行页与 SLAM 页显示实际原因，例如“后方雷达覆盖不足，暂不允许后退”。旧车端缺字段时显示“车端不支持”或“诊断信息不可用”，不能默认显示已启用或安全。

## 6. 测试与通过标准

先增加能复现当前失败的测试，再实施修复。沿用现有避障、ROS 适配、API、前端和桌面代理测试，补充以下有区分度的场景。

| 场景 | 必须验证的结果 |
| --- | --- |
| 真实扫描回放，前方可用、后方缺失 | 复现旧版拦截；新版仅在完整所需运动区域安全时允许前进 |
| 后方盲区下后退、侧方盲区下横移 | 对应动作被拦截，给出正确方向与原因 |
| 无障碍、单点小障碍、窄通道、双侧封堵 | 可行时通过；会接触车体或不足余量时停车 |
| 全无效、部分无效、零/NaN/Inf、角度裁剪 | 按已确认的传感器语义处理；未知不能被批量当空地 |
| 雷达反装、位置偏移、跨扫描运动 | 左右和前后判断正确，时间与坐标补偿正确 |
| 当前空间与未来扫过区域重叠 | 不因后方无关盲区一律停车，也不因此忽略近障或新扫过的未知区域 |
| 有曲率的动作、非圆车体转动 | 角部、侧面与停车轨迹均检查，不穿过盲区 |
| 遮挡后的绕行路径 | 可安全逐段探索；无法证明安全前缀时停车，不一次批准整条未知路线 |
| 接近同分、左右交替噪声 | 单次方向锁定，不能左右摆动 |
| 雷达/TF/里程计超时或跳变 | 任意阶段归零，解除故障不自动恢复 |
| 松手、停止、急停、红灯、目标丢失 | 任意绕行阶段终止，无旧目标或旧指令恢复 |
| 主动开关关闭、设置未确认、配置损坏 | 不执行主动绕行；防撞与相应故障停车仍有效 |
| Nav2 导航和取消任务 | 不增加共享层转向，不破坏任务取消与结果处理 |
| 松手后查看状态或重连 | 当前停止与上次安全拦截均可解释；旧车端兼容 |

闭环模拟中每步更新车辆位姿、障碍相对位置与可见范围，独立检查车体是否碰撞、是否恢复朝向、是否遵守时限；不能只断言状态名称改变。除理想全周扫描外，必须包含真实样本对应的缺失模式。被测算法和验收碰撞判定不要共用同一实现，以免共同漏检。

运行相关车端 Python 回归、前端测试与构建、桌面代理测试；按新增失败和改动范围决定补充检查，不复制旧测试数量冒充本轮结果。检查 `/cmd_vel` 发布者数量。测量真实车端控制循环耗时与命令到输出的延迟；若达不到配置的控制周期，先优化扫描缓存或几何计算，并验证故障停车时序，不能靠无限延长数据超时解决。

4. 记录当前源文件、安装引用、前端静态资源、服务入口与持久配置的哈希。保存可回退版本；保留运动标定、雷达/相机配置、地图、数据库、避障设置及其他用户配置。

### 7.2 上传、构建与启用

将 `scripts/prepare_avoidance_release.py`、`scripts/stage_avoidance_release.py` 中固定日期、旧基准目录和输出路径参数化或更新为明确版本；基准取实际活动目录。生成包含源码、前端资源、清单和哈希的新版本，上传到新的独立目录，避免覆盖正在使用的目录。沿用适当的增量或符号链接构建，控制磁盘开销。

## 9. 现场低速验收

先静止核对雷达前后左右、车体真实尺寸、车轮/突出部件和近处回波，确认现场人员能急停。依次完成无障碍短距离直行、左侧绕行、右侧绕行、双侧封堵、松手中断、急停中断、传感器失效停车。先用较大纸箱，再测试用户此前放置的水壶；记录水壶是否进入雷达扫描面。无地图手动测试应能进行，Nav2 行为另行验证。

每项保存有界的扫描、里程计、请求速度、最终速度与阶段记录，标注距离、速度、通过/失败和原因。开放通道下应低速绕过且不接触障碍；路径不能安全验证时停车；结束后确认零速度与静止状态。现场不能配合或障碍低于扫描面时如实记录限制，不能把软件模拟结果写成实车通过。

不增加“垃圾、杂物、危险品识别”作为本轮任务，也不把普通目标检测结果宣传为危险品识别。二维雷达扫描面外障碍仍不属于本功能已解决的检测能力。
