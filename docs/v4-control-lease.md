# v4 控制租约实施状态

决策控制器拥有 controller_id、control_epoch 和唯一 owner。初始没有租约，最终运动输出归零。获取租约要求 stop 模式、有效的新鲜里程计和静止状态；续约要求同一控制器、代际、owner 和递增序号。有效期固定三秒。

过期、释放和急停更换代际。过期后的迟到续约不能恢复运动。控制器重启生成新的身份和代际。租约检查同时放在避障前和最终 Twist 输出前，避免避障内部状态继续输出运动。

ROS 请求与回执为 `/robot/control_lease/request` 和 `/robot/control_lease/status`。Web 节点接收回执并加入状态快照。协议使用 `controller_id`、`control_epoch`、`owner`、`sequence` 和 `op`（acquire/renew/release）。这只是内部协议，暂不向业务页面开放。

车端 `/api/control-lease` 已提供查询与请求接口。请求通过独立 request_id 等待控制器回执，未收到回执时明确返回 confirmed=false。stop 操作更换代际，不能通过旧续约恢复。

主机增加进程内单租约管理器和每秒续约后台任务，续约前复核用户有效性、原业务权限及实车绑定；丢失确认则尝试停止，不自动重新获取租约。获取过程中收到停止后，迟到的获取回执不会被保存为活动租约。进程正常结束时尝试停止已持有租约。

全局「停止车辆」调用主机 `POST /api/v1/robots/stop`，由服务器解析绑定车辆，也可用 `POST /api/v1/robots/{robot_id}/stop`。主机撤销当前和正在获取的租约后直接调用车端停止。响应分别报告发送、控制器回执和静止确认。静止确认依赖停车回执后的新鲜里程计，并复核控制代际。

巡检和运输的运动动作已通过主机获取独占租约。车端在规划、派发、Nav2 接受目标、行驶及站点停留期间校验租约。暂停、取消、等待交接和终态仅释放回执对应的租约，迟到回执不能撤销新代际。

搜索启动接受 `run_id`，相同请求可重试。历史状态通过 `GET /api/control/search?run_id=...` 查询。取消未派发的 ID 会持久化取消记录，迟到启动返回该记录。静止观察全程维持搜索停车锁，单独检查能力与实车验收。路线搜索仅允许匹配路线的停留和换站，并要求运动租约。无地图自动巡航已从当前搜索入口移除。

主机在路线搜索开始和继续前复核能力与验收，再签发本次运行的租约。丢失派发响应时按运行 ID 核对记录和租约，无法确认则停止续约。搜索和导航状态确认暂停或结束后，主机释放对应租约。移动搜索性能记录还须匹配车端上报的构建号、源码指纹及模型。

独立导航预览绑定申请人、物理车辆、控制器身份和代际。开始导航时重新检查能力和实车验收，消费一次预览并获取导航租约。停止或接管后要重新预览。

选择手动驾驶或开始 SLAM 建图会撤销现有执行，并等待控制器和新鲜里程计确认停车。随后获取与模式匹配的租约。浏览器收到仅对当前账户和车辆有效的驾驶标识，按住、松开和转向使用同一标识与递增序号。主机、车端 HTTP 和决策控制器均拒绝迟到指令。松开可保留本次驾驶，完整停车或离开驾驶模式后需重新获取控制权。旧式自动巡航和跟随入口目前未签发租约。

桌面正常退出时撤销后续步骤并尝试停车。助手重启后先对账，推进任务需要显式恢复。

模拟验证覆盖超时、序号乱序、切换模式、撤销和重启。控制器模拟检查包含松键后迟到前进时的 Twist 输出。仍需在实车低速下验证接管、主机失联和故障停车。
