# v4.0.0 桌宠浏览器验收

本轮于 2026-11-05 使用本机 Chrome 和 agent-browser 检查实际 React 页面。主机使用正式认证、会话、消息、计划确认、事件流和独立停车接口，数据库位于临时目录。模型回答、车辆状态、停车回执及资源能力核验由夹具提供。

## 已验证的交互

| 场景 | 观察结果 |
|---|---|
| 默认入口 | 登录后仅显示小巡检车，点击展开浮窗 |
| 拖动与刷新 | 拖动后刷新，位置恢复；拖动结束不会误触展开 |
| 窗口缩放 | 320 × 568 和 390 × 700 内浮窗受边界约束，恢复宽屏后回到用户原位置 |
| 顶部停车入口 | 长任务卡的浮窗保留顶部控制区，命中检测确认停车按钮可点击 |
| 计划内容 | 搜索卡明确显示巡检一圈、找到目标后停车、等待人工处理 |
| 事件重连 | 首次查询计划返回 503，事件重放后成功显示待确认卡 |
| 自动提醒 | 新待确认事件展开浮窗，原输入框保持焦点；已关闭的同一提醒保留徽标 |
| 刷新后的提醒 | 待确认引用保存在当前账户下，刷新后复核状态并保留徽标，浮窗保持关闭 |
| 未发送草稿 | 关闭浮窗或收到其他会话的确认事件时保留草稿，可显式进入待确认会话 |
| 输入隔离 | 在可驾驶页面的助手输入框输入 W 和空格，得到文本 `w `，车辆请求计数为零 |
| 重复确认 | 重复点击确认后只保存一条执行记录 |
| 模型等待时停车 | 服务端确认模型正在等待后点击顶部停车，取得控制器和静止回执，模型随后恢复 |
| 减少动效 | 系统开启减少动效后，角色动画为 none |
| 对话窗布局 | 宽屏与 320 像素窄屏下，消息区域独立滚动，输入框位于可见浮窗内 |
| 退出登录 | 桌宠移除，当前账户的事件游标与待确认缓存清除，拖动位置偏好保留 |

复测中修复了浮窗遮挡顶部控制区、缩窄窗口覆盖原位置、刷新丢失待确认徽标，以及长消息挤出输入框的问题。任务卡补充了固定的人工处理流程和能力拒绝原因。

## 复现入口

在仓库根目录启动隔离夹具，退出进程后清理临时数据库。

```powershell
python tests/assistant_browser_fixture.py 18741
```

在另一个窗口启动前端。

```powershell
$env:BUSINESS_PROXY_TARGET = "http://127.0.0.1:18741"
Set-Location web-console
npm run dev -- --port 18742
```

打开 `http://127.0.0.1:18742/#/login`，使用临时库中的 admin / admin123。夹具的 `POST /fixture/notify` 生成持久化的待确认事件，`GET /fixture/evidence` 返回检查计数。向助手发送“模拟模型等待”后，先确认计数中的 model_waiting 为 true，再点击顶部停车。

夹具使用模拟核验并且关闭后台执行器，仅监听本机回环地址。部署时使用正式主机入口。
