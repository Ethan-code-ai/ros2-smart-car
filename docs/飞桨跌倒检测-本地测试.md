# 飞桨 PP-Human 跌倒模型：本地运行与测试

## 模型与环境

使用飞桨官方 PP-Human 流程：PP-YOLOE 人员检测与跟踪 → HRNet/DARK 17 点骨骼 → ST-GCN 跌倒/其他分类。
识别由训练过的 ST-GCN 完成，不使用现有宽高比规则。

- 原始模型包：`D:\智能小车\pphuman_models\`，保留用户下载的三个 ZIP。
- 解压模型：`D:\pphuman-runtime\models\`。使用英文路径以兼容原生模型文件加载。
- 官方代码：`D:\智能小车\third_party\PaddleDetection\`。
- 官方代码版本：`release/2.9`，commit `b25522a0f4bde8c80603f3ba5e3472059972e3b5`。
- 独立环境：`D:\智能小车\ros2-smart-car\.venv-pphuman311\`。
- Python：独立的 Python 3.11 运行时，存放在 `D:\pphuman-runtime\python\`。
- 飞桨：3.2.2 GPU / CUDA 12.6。原始 `.pdmodel` 使用 `FLAGS_enable_pir_api=0` 加载。
- cuDNN：9.9.0.52，与此 wheel 编译使用的 cuDNN 9.9 对齐。
- 数据集：`D:\智能小车\dataset\`，URFD cam0 RGB 69 段，30 段跌倒 + 39 段 ADL，缺 adl-08。

官方介绍、权重与计分来源：

- [PP-Human 行为识别文档](https://github.com/PaddlePaddle/PaddleDetection/blob/release/2.9/deploy/pipeline/docs/tutorials/pphuman_action.md)
- [官方视频流程](https://github.com/PaddlePaddle/PaddleDetection/blob/release/2.9/deploy/pipeline/pipeline.py)

## 本机复现

在 PowerShell 执行：

```powershell
Set-Location 'D:\智能小车\ros2-smart-car'
$env:PYTHONIOENCODING = 'utf-8'
$py = '.\.venv-pphuman311\Scripts\python.exe'

# 检查 GPU（不会自动退到 CPU）
& $py -c "import paddle; print(paddle.__version__); print(paddle.is_compiled_with_cuda(), paddle.version.cuda()); print(paddle.device.cuda.device_count())"

# 评测程序的计分和数据安全测试
& $py .\tests\test_eval_pphuman.py

# 全量 GPU 推理并评测；相同模型/代码/数据的已完成序列自动复用缓存
& $py .\demo\eval_pphuman.py all --device GPU

# 已有推理缓存时，只生成评测报告，无须再次推理
& $py .\demo\eval_pphuman.py evaluate

# 强制重新推理
& $py .\demo\eval_pphuman.py all --device GPU --force
```

首次可以只跑两段确认整个链路：

```powershell
& $py .\demo\eval_pphuman.py all --device GPU `
  --sequences fall-04,adl-31 --out-dir .\demo\results-pphuman-smoke
```

完整结果目录：`D:\智能小车\ros2-smart-car\demo\results-pphuman\`。

```text

metrics.json    环境、权重 SHA256、数据量、事件级和帧级指标

events/         每段开始/结束事件
```

推理缓存位于 `.urfall-work\pphuman\predictions\`。每帧记录人员框、HRNet 关键点、ST-GCN 新判断、告警保持状态。
缓存指纹包含三模型、配置、官方代码 commit、运行环境及数据 ZIP SHA256；不混用旧 YOLO 缓存。

## 测试口径

1. 原始 PNG 顺序读取，保留官方帧号，使用 30 FPS 数据时间。
2. 每段重新初始化跟踪、骨骼缓冲、告警历史。跟踪参数采用官方 release/2.9 配置（BoT-SORT）。
3. 遵循官方 50 次骨骼观测组成的非重叠动作窗口和 `[384, 512]` 框内归一化；丢失轨迹时按官方缓冲逻辑分类。
4. `argmax` 的 class 0 为跌倒，class 1 为其他，未针对 URFD 调参。
   官方输出的 score 为原始 logit，不是概率；原样保存在缓存中，不拿它当作 0～1 置信度。
5. 使用官方 80 帧显示保持；同时提供仅统计原始模型判断的 `raw_event_summary`。
6. 与旧方案相同：跌倒段报出一次算召回；所有 ADL 告警都算误报，包括主动躺下。
7. 另列“跌倒过渡开始后新产生的模型判断”，防止跌倒发生前的错误告警被算作成功检测。
8. 按官方视频实现，末尾不足 50 次观测的骨骼缓冲不额外分类；缓存保留剩余观测数用于诊断。

**官方模型训练包含 URFD，且部分业务数据未公开。此处是模型在本地数据上的回归测试，不能作为独立泛化准确率。**
真实小车部署还需要未参与训练的实验室、低视角、主动躺下与蹲坐视频评测。

## 环境安装记录

旧 Conda Python 的 SSL 组件不完整，因此创建独立 Python 3.11 环境。飞桨 2.6.2 要求本机缺少的 cuDNN 8，实际改用官方 3.2.2 CUDA 12.6 wheel 及匹配的 NVIDIA 运行库。

安装依赖清单：`demo/requirements-pphuman.txt`。使用本机下载的 uv：

```powershell
& 'D:\pphuman-runtime\tools\bin\uv.exe' pip install `
  --python .\.venv-pphuman311\Scripts\python.exe `
  -r .\demo\requirements-pphuman.txt

# 官方 wheel 元数据锁定的是 cuDNN 9.5，但该 wheel 实际编译版本为 9.9。
# 先按依赖安装，再显式覆盖这一运行库，以消除运行时版本不匹配提示。
& 'D:\pphuman-runtime\tools\bin\uv.exe' pip install --no-deps `
  --python .\.venv-pphuman311\Scripts\python.exe nvidia-cudnn-cu12==9.9.0.52
```

`demo/requirements-pphuman-lock.txt` 记录本机实际安装版本。因上述官方依赖元数据冲突，重建环境采用这里的两步安装命令。

GPU FP32 推理，未使用 TensorRT。与旧方案的 FP16 或不同硬件 FPS 应分别说明。
